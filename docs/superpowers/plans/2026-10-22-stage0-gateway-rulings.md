# Stage 0 gateway: execution rulings

Decisions made during subagent-driven execution of docs/superpowers/plans/2026-10-22-stage0-gateway.md. Each has its reason and what it costs if wrong. Review and override any of them.

- R1 Ruling: Task 4 adds `UpstreamError.kind: str` in {"timeout","connection","upstream_4xx","upstream_5xx"} set at raise time; T8 and T9 use `e.kind` for error_kind / smoke rows — the spec requires a fixed error vocabulary and no task defined the mapping — cost if wrong: a rename in two call sites.
- R2 Ruling: `smoke_main()` and `discover_main()` live in `gateway/probe.py`; `scripts/*.py` are 3-line wrappers calling them; the T9 test imports `from gateway.probe import smoke_main` — scripts/ is not importable — cost if wrong: none functional.
- R3 Ruling: no module-level `app`; T9 adds `create_app_from_env() -> FastAPI` to gateway/app.py and the runbook uses `uvicorn --factory gateway.app:create_app_from_env` — importing gateway.app must not require secrets — cost if wrong: one-line runbook change.
- R4 Ruling: T8 tests may add dev dependency `asgi-lifespan>=2.1` (LifespanManager) or enter `app.router.lifespan_context(app)` manually; implementer's choice — httpx ASGITransport does not run lifespan — cost if wrong: one extra dev dep.
- R5 Ruling: AutoPassthrough: missing `model` → reason "default: hooshyar auto"; any explicit `model` value including "auto" → reason "explicit model requested" (test is authoritative) — spec is silent; test text is the more specific — cost if wrong: a reason string.
- R6 Ruling: commit trailers name the model each subagent's harness reports (Haiku/Sonnet/Opus) rather than the dispatch text — the harness attribution reflects the actual author and the system prompt defers to it — cost if wrong: cosmetic trailer edits.
- R7 Ruling: when the budget guard downgrades auto→small, that request's fallback chain excludes "frontier" (small→medium only) — spec §5 "Above the cap, the frontier tier needs an explicit request"; plan's fallback map would otherwise escalate a capped request to frontier on a small-tier 5xx — cost if wrong: capped requests fail instead of escalating when small+medium are down.
- R8 Ruling: over-cap auto request when the small tier is unconfigured → keep target "auto" with reason "budget_cap_unenforceable" instead of 502 — "router failure must never fail a request auto could serve" outweighs the cap when the cap cannot be enforced; with all tiers empty at first deploy the cap is otherwise a guaranteed outage — cost if wrong: an over-cap app keeps spending until tiers are configured (logged per request).
- R9 Ruling: 400 client errors log error_kind=None (status 400 distinguishes them); no new vocabulary kind in Stage 0 — vocabulary is fixed by plan and status already carries the information — cost if wrong: a later analysis filter on status instead of kind.
- R10 Ruling: prompt_chars counts string contents only (decision 6 as written); list-of-parts contents deferred as minor — cost if wrong: undercounted length for multimodal-style requests.
- R11 Ruling: an exception after the upstream response arrived returns 500 rather than re-serving via auto — re-serving would double-bill and the response may be partially consumed — cost if wrong: rare 500s on malformed upstream JSON.
- R12 Ruling: budget_cap_unenforceable requests (target auto) also exclude frontier from the fallback chain — consistent with R7 (capped requests never escalate to frontier); auto is always tried first so serveable requests still succeed — cost if wrong: one-line change if frontier fallback is wanted there.
- R13 Ruling: Important #4 → option (b) for Stage 0: discovery probes whether Hooshyar honours stream_options.include_usage; runbook documents that streamed cost/budget are only counted when usage is present; no request injection yet — injecting an unverified parameter into every streaming request could break all streaming if Hooshyar rejects it; prices are empty at Stage 0 so the cap is inert anyway — cost if wrong: streamed spend invisible to budget/cost until Stage 2 adds injection after discovery confirms support.
- R14 Ruling: 4xx upstream error objects are returned to the calling client (never logged, never in str(e)); 5xx/transport stay generic — privacy constraint covers logs/stdout, and the body describes the caller's own request — cost if wrong: an upstream 4xx body that echoed sensitive content would reach only the same caller.
- R15 Ruling: explicit request for an unconfigured tier → 400 invalid_request_error "model tier '<t>' is not configured" with error_kind None (R9 precedent), attempts logged; /v1/models lists auto + configured tiers only — cost if wrong: a client relying on 502 retry semantics for misconfiguration.
- Final: parked — aread() failure on a stream 4xx classified as retryable transport error — Ruling: rare; worst case is a fallback instead of returning the 4xx — cost if wrong: an occasional extra upstream call.
- Final: parked — client_error and shadow usage unbounded/unfiltered — Ruling: no user text; size bounded by upstream; cap in Stage 2 if logs grow — cost if wrong: larger log lines / responses.
- Final: parked — upstream 401/403 error object reaches the client (could look like the client's own key is wrong) — Ruling: follows R14; runbook smoke test catches a bad gateway token — cost if wrong: confusing error for clients during misconfiguration.
